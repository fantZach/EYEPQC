# Windows PC foreground CLI / EXE (2026-10-15)

## Scope and artifact

Added `pc/src/host/eyepqc.py`: `run`, `check`, `status`, interactive `account`.
`run` owns one local relay and optionally one SSH child; Ctrl+C cleans up only those children.
Startup refuses an occupied local 8765 before reading configured materials. SSH exits stop the owned relay;
there is no automatic takeover, daemon, PID killing, account switching or reconnect loop.

Built with isolated `build/pc_cli/venv`, Python 3.12.10, PyInstaller 6.22.3, console/onefile, no added data.

- Artifact: `build/pc_cli/dist/eyepqc.exe`
- Size: 10,266,628 bytes
- SHA-256: `c3989e2bb63ea64360490c8a61f6c1f1a99ac3d85508ca74140a47f8cf772e8a`
- Rebuild command: `./pc/build_exe.ps1` (initial dependency setup adds `-InstallDependencies`).

Config, accounts, certificates, SSH keys and board identity are external; no actual private file was read
or copied for packaging. A local ignored `build/pc_cli/dist/eyepqc.json` contains absolute paths only,
references the existing old `accounts.json`, COM7 and the existing tunnel files. It was not run or checked
against real secret materials. `accounts-new.json` was not selected. The example config remains portable,
relative to its own directory, with automatic CDC discovery.

## Initial packaging-only limits

No real relay/SSH/USB/phone workload was migrated to the EXE. The occupied 8765 listener was preserved;
there is no claim that the frozen EXE successfully opened a production listener or tunnel.
Before switching, normally stop both old standalone services; a surviving old SSH reverse listener can
cause the new SSH child to fail and the new relay to shut down. Windows OpenSSH Client is external.
CLI errors expose static diagnostic categories and numeric SSH exit status, never raw malformed account/JSON input.
This artifact is unsigned; an installer and background service are outside this change.
