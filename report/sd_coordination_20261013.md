# SD 部署协调记录（2026-10-13）

用户授权本聊天统筹 Board、Android、PC 三个独立聊天，目标为 SD 卡部署与冷启动。

| 聊天 | 独占范围 / 任务 |
|---|---|
| EYEPQC Board：SD启动与冷启动 | 唯一 JTAG、调试 UART 与板上 SD 操作者；识别卡、只读目录、备份被替换文件、匹配镜像部署、冷启动采集 |
| EYEPQC PC：转发服务与部署 | PC 服务状态、板测前暂停/板测后恢复方案及非秘密日志；不操作 JTAG/SD/调试 UART |
| EYEPQC Android：播放器与配对 | mobile 修改与 APK/握手接入验证；不操作板卡/PC 进程 |
| 本协调聊天 | 用户物理动作、共享目标/steps/progress 与跨项目验收归档 |

当前分两步推进：先用已存在的 G0/FSBL 构建和严格 UART 验收证明 SD 独立启动、物理复位和 30 分钟冷启动，
随后收口 G6 视频系统自主启动需要的长期私钥装载/会话随机材料；前者不能替代后者。
现有 G6 BOOT.BIN 仍等 JTAG 的开发态私钥/seed mailbox，不能只复制镜像便宣称独立视频握手完成。

板上 SD 不是 Windows 已挂载磁盘。卡原内容未知，不格式化或写原始盘；先确认目标卡/文件系统并列出目录，
将被替换的 BOOT.BIN 等文件备份到本机并校验，才执行可恢复的启动文件更新。
卡无法安全访问、启动拨码或完整断电需要人工时，由本协调聊天向用户提出具体动作，不以模拟值冒充物理证据。

用户报告手机正常显示视频、约 40 fps 可接受，更新为近期 MVP 性能口径；它不是 G8 定时长/故障完整通过。
三个聊天共享工作区，只提交所属源码和独立报告；共享说明由本聊天维护，不使用全仓暂存或丢弃他人改动。
