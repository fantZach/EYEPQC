# M08：全 PL AES-128-GCM AXI4-Stream IP

复用 M06 的 secworks AES 核和 M07 的 GHASH，不更改开源 AES 逻辑。
G3 合成时仅在 `aes_sbox.v` 文件尾恢复 `default_nettype wire`，避免该编译指令
影响随后生成的 Vivado BD Verilog。
`aes_gcm_axis.sv` 将 32-bit AXI4-Lite 控制与 32-bit AXI4-Stream 数据连接到
`aes_gcm_encrypt.sv`。按 [NIST SP 800-38D](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38d.pdf)，
每包依次计算 `H=AES_K(0)`、`E_K(Nonce||1)`，
用 `Nonce||2` 开始 CTR，仅将密文送入 GHASH，最后输出完整 16 字节 Tag。
一次只处理一个包；串行 GF 乘法节省资源，M08 未做未经测量的并行化。

## 软件接口

| 偏移 | 访问 | 含义 |
| --- | --- | --- |
| `0x00` | 写 | `1` 启动、`2` 零化/中止、`4` 清完成中断 |
| `0x04` | 读 | bit0 busy、bit1 done、bit2 error；`irq=done` |
| `0x08` | 读写 | 明文长度，0..1400 字节 |
| `0x0c` | 读写 | AAD 长度，0..64 字节 |
| `0x10` | 读 | 完成包计数；零化保留，硬复位清零 |
| `0x14` | 读 | IP 标识 `0x47434d31` (`GCM1`) |
| `0x20..0x2c` | 只写 | 128-bit Key，首 32-bit 字位于低偏移 |
| `0x30..0x38` | 只写 | 96-bit Nonce，同上 |
| `0x40..0x7c` | 只写 | 最多 64 字节 AAD，同上，未用部分补零 |
| `0x80..0x8c` | 只读 | 完成后的 128-bit Tag，高字在先 |

Key/Nonce/AAD 不可读；Busy 时配置写入返回 `SLVERR`，零化例外。
超长 AAD/明文的启动命令返回 `SLVERR`；流内非法 `TKEEP/TLAST` 置错误并停止，
必须零化才能复用。出错前已经送出的密文须由调用方整包丢弃。
所有字节寄存器均为网络字节序：例如 Key `00112233...` 向 `0x20` 写 `0x00112233`；
AXIS 字节 0 位于 `TDATA[7:0]`，只接受低位连续 `TKEEP`（`1/3/7/f`）。
流输入只含明文；输出为连续的 `ciphertext || tag`，总字节数 `payload_length+16`，
仅最后一拍允许非满 `TKEEP`，并拉高 `TLAST`。零长度明文无需输入拍，但仍输出 Tag。
G2 上板发现：密文尾块之后再单独开始 Tag 会使 DMA 丢失尾块中的有效字节；
现复用已有 `axis_byte_packer.sv` 跨密文/Tag 边界连续打包，仿真固定检查非末拍 `TKEEP=f`。
调用方必须为同一 Key 的每包提供唯一 Nonce；M10 会话管理负责此约束，
本 IP 的包计数仅供状态/统计，**不是** Nonce 生成器。

## 验证

```powershell
& ./.venv/Scripts/python.exe sim/tb/test_m08.py
& 'D:/AmdDesignTools/2026.1/Vivado/bin/vivado.bat' -mode batch -source prj/check_m08.tcl -log build/m08_demo.log -journal build/m08_demo.jou -tclargs build/vivado/m08_demo
```

实际 RTL 仿真与软件 AESGCM 对比：80 组 M00 向量、20 组 NIST 向量，外加
同 Key 换 Nonce、同 Nonce 换 Key 的 2 组连续包；包含空包、1～17 字节尾块、
64 字节 AAD、1400 字节载荷、随机 AXIS 背压。每个密文字节、Tag、长度、
`TKEEP/TLAST` 均检查；软件对 Key/Nonce/AAD/密文/Tag 篡改均拒绝。
仿真还覆盖 AXI-Lite 通道错开、忙时拒写、长度拒绝、非法 `TKEEP`、
提前 `TLAST`、忙时零化、硬复位和密钥清除。
结果：`AES_GCM_AXIS_PASS cases=102 stalls=2652 limits=1 busy_write=1 zeroize=1 reset=1`。

Vivado 2026.1 独立 OOC 综合（`build/vivado/m08_ooc_g2`）：6370 LUT、5679 FF、
0 BRAM、0 DSP；10 ns 时钟估计 WNS +2.365 ns、WHS +0.240 ns。
OOC 缺少 `HD.CLK_SRC`，该估计不是布线后板级时序。
独立 [G2](g2.md) 工程已将 M08 接入 DMA 并通过 21 组上板验收；
M05 摄像头工程仍保持原 DMA 回环，另建的 [G3](g3.md) 工程已接入实拍 JPEG 并通过离线验收。
