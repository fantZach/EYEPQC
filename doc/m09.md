# M09：ML-KEM-512 PS 软件基线

## 实现与信任边界

采用 [PQCA mlkem-native v1.3.0](https://github.com/pq-code-package/mlkem-native/releases/tag/v1.3.0)，
固定提交 `398050c877ff4353c96305c6434b63528accfc37`；`board/src/third_party/mlkem/`
保留构建所需的上游纯 C 文件和 [原始许可证](../board/src/third_party/mlkem/LICENSE)，
按上游 `Apache-2.0 OR ISC OR MIT` 三选一采用 MIT。未修改上游源码；
不启用原生汇编、动态分配和随机化 API。PC 与 A9 都构建同一份 C 代码，
参数集固定 512。A9 仅链接 Decaps 和密钥检查，不依赖文件系统或操作系统。
核心的临时栈数组由上游 `mlk_zeroize` 清除；板端加载缓冲、临时共享秘密和
清理命令均显式清零，错误只返回状态码，不打印密钥。

静态密钥对在 PC 离线生成，`board/output/m09/` 内的私钥、公钥、密文和期望共享秘密
均被 Git 忽略。主机 Encaps 前核对固定公钥的 SHA-256；上板前再核对私钥内嵌公钥。
JTAG `load` 把私钥从传输缓冲复制进板卡私有 DDR 后清空传输缓冲，`decap`
在板卡私钥上运行，`clear` 擦除私钥与输出。断电后密钥丢失；这是离线开发流程，
JTAG 和 PC 上的测试私钥文件均不提供生产级密钥保护。主机 Python 包装返回的
不可变 `bytes` 无法可靠清零，在线握手应改用受控的 C 缓冲和正式安全随机源。
无效但定长的密文按 FIPS 203 隐式拒绝生成不同共享秘密，不把它当解析错误；
长度错误由主机/JTAG 边界拒绝。

## 复现

```powershell
python sim/tb/test_m09.py
python pc/src/host/m09.py build
python pc/src/host/m09.py keygen
python pc/src/host/m09.py encaps
python pc/src/host/m09.py decaps
$env:EYEPQC_M09_VITIS = (Resolve-Path 'build/vitis/m09_fresh').Path
& 'D:/AmdDesignTools/2026.1/Vitis/bin/vitis.bat' -s board/prj/build_m09.py
python pc/src/host/m09.py board --workspace build/vitis/m09_fresh
```

`keygen` 拒绝覆盖已有私钥；复测同一密钥无需再次运行它。
板测需 JTAG、已运行的 `hw_server` 和有效 M01 XSA；不需要网口或摄像头。
可用 `EYEPQC_M09_XSA` 指向别的板卡 XSA。构建脚本记录 XSA、源码、ELF 哈希和
ELF 自有 DDR 地址；主机上板前逐项复核。A9 链接脚本主栈增至 32 KiB。

## 2026-09-29 实测

- PC：NIST ACVP 的 25 组 KeyGen、25 组 Encaps、10 组 Decaps 完全相符；
  另跑 1000 次重复 Decaps、篡改密文和错误长度/损坏私钥测试。
- A9：与 PC 相同的 ACVP 向量 1000 次、离线静态密钥 1000 次、
  单比特篡改密文 1000 次均完成；前两组共享秘密一致，篡改组不同。
- A9 `-O3`、666.667 MHz：静态密钥 1000 次共 7,952,648,699 CPU 周期、
  11,928,972 µs，平均约 7.953 M 周期、11.929 ms/次。
  ACVP 为 11,930,128 µs，篡改组为 11,928,996 µs。
- 栈水位约 12,860 字节（相对测量函数入口的 canary 高水位），
  32 KiB 主栈；未启用堆分配，堆占用 0。密文长度被固定为 768 字节，
  1000 次篡改解封装未出现超时、异常退出或错误共享秘密接受。

板端结果和 JTAG 日志保存在忽略的 `board/output/m09/`；
本阶段未接 TCP、HKDF 或视频流，它们分别属于 M10/M11/G6。
