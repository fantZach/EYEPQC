# M06：AES-128 加密核心

复用固定提交 `80dc4718e1dcbbdb4b0dd1bdb393d8f7b98981dc` 的
[secworks/aes](https://github.com/secworks/aes)（BSD-2-Clause），不重写 AES。
现有 `aes_axi_lite.sv` 将开源核固定为 AES-128 Encrypt；AXI4-Lite 为单笔事务，
32-bit 寄存器按高字在先映射 128-bit Key、输入和输出。地址、状态位、字节序、
zeroize 及图片上板复现见 [固定图片 AES-GCM MVP](aes_mvp.md)。
M06 只验 AES 块加密，不把 PS GHASH 的图片 MVP 或 M05 DMA 回环冒充 M08 全 PL AES-GCM。

## 验证

```powershell
& ./.venv/Scripts/python.exe sim/tb/test_aes_mvp.py
```

实际开源 RTL + AXI wrapper 与软件黄金参考逐块比对：1 个 NIST AES-128 KAT、
12 组确定性随机 Key/明文；还覆盖同一扩展密钥连续两块、更新 Key 后旧密钥
不能继续加密、加密忙时硬复位及上游轮密钥清除。AXI AW/W 错开、背压、
WSTRB、非法地址、忙时拒写和运行中 zeroize 沿用同一 testbench。
测试输出 `AES_AXI_PASS vectors=13 core_cycles=53 consecutive=2 key_update=1 hard_reset=1`。

在开源核 `next` 被采样到 `result_valid` 被采样之间实测 53 个 100 MHz 周期，
即约 0.53 μs/块；不包含 AXI 寄存器传输、Key 初始化、DDR/JTAG 或 GHASH。
现有 `build/vivado/aes_mvp_2/m01.runs/system_aes_0_0_synth_1/system_aes_0_0_utilization_synth.rpt`
记录 AES AXI IP 综合资源：2600 LUT、2566 FF、0 BRAM、0 DSP。
其全系统原生实现 100 MHz，WNS +0.767 ns、WHS +0.089 ns；这是全系统时序，
不当作单独 AES IP 的最高频率。M06 RTL 未改，故复用已有 bit/XSA 和
[图片 MVP](aes_mvp.md) 的实物 AES 证据，不重复下载板卡。

M06 判据已满足；G2 的 DMA→AES-GCM→DDR 与完整 Tag 比对仍属于 M08 集成。
开源核未做侧信道掩码或故障注入防护，不作为生产安全核宣称。
