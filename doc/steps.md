# EYEPQC 实施顺序与验收范围

2026-10-31：用户确认 SD 本地身份版正常连接，定为正式版第一版，并反馈此前首次连接问题修复。
本次整理未新增板卡、手机或公网测试；不能由连接成功推定全部故障、冷启动或长稳门禁通过。
部署从 [四端新手教程](deployment/README.md) 开始，当前基线见 [版本记录](releases/first-stable.md)。

## 当前主链路

摄像头 → 板端 JPEG / AES-GCM → USB Slave → Windows PC → 可选公网中转 → Android 解密播放。
SD 保存固定身份及可更新随机状态，日常使用 `eyepqc run`。先前 PC 注入秘密的方式仅保留历史兼容。
账号、自动配对、双阶段 ML-KEM 握手、定时/手动换钥和单观看端显式接管已实现。
更改身份或恢复运行卡必须按 [SD 身份说明](g6_sd_identity.md) 操作，不覆盖已用随机状态。

## 门禁定义

| 门禁 | 必须独立记录的内容 |
|---|---|
| G0 | 工具/板卡匹配、DDR/UART、SD 冷启动、LED、复位与所需外设 |
| G1 | 摄像头配置、实际 JPEG 采集与解码 |
| G2 | AES-GCM 标准向量、边界长度、错误拒绝与硬件结果 |
| G3 | 摄像头→DDR→加密的实际数据通路 |
| G4 | 明文 USB 视频、吞吐与控制收发 |
| G5 | 固定密钥加密视频、标签验证与帧统计 |
| G6 | 动态 ML-KEM、Finished、START/STOP、换钥与认证视频 |
| G7 | 长期运行、USB/进程/相机故障、重连与拒绝旧会话，子项分开 |
| G8 | Android 局域网登录、显示、接管、换钥与故障恢复 |
| G9 | 启用公网时的隧道、TLS、不同网络、带宽及中断恢复 |

G0 历史自检采用用户同意的十分钟例外；不改成三十分钟，也不替代当前视频固件全部冷启动检查。
G7 历史运行约五十分钟由用户例外接受，不是满两小时实测；故障子项未据此通过。
当前用户连接反馈和历史约 45 fps 不能代替新版本长稳、自动换钥或故障测试。
验收由用户统一进行，未执行填“未测”，失败保留实际失败；见 [验收表](deployment/ACCEPTANCE.md)。

## 后续顺序

先维护当前 SD/USB 四端可用基线，再按实际需要补充验收、正式签名与证书部署。
生产熵源、受保护存储、安全启动/JTAG 防护是独立任务，不能通过改名关闭。
**板端以太网保持最后的可选项**，不是当前 USB Slave + PC 联网的前置条件。
