# M02：OV5640 SCCB 配置

Ponytail：复用官方寄存器事实和现有 Icarus/Vivado；不复制无 ACK 检查的官方驱动，
不增加 Python 依赖、网络、DMA 或视频采集框架。heartbeat 测试已按用户要求移回 `sim/tb/`，M01 回归保留。

## 接口与边界

`sccb_master.sv`：单一 `clk`、同步低有效 `resetn`，空闲时接受单周期 `start`，
锁存 `read_not_write/reg_addr/write_data`；忙时忽略新请求。固定 7-bit 地址 `0x3c`，
16-bit 寄存器地址、8-bit 数据。SCL/SDA 只驱动 0 或高阻，外部必须有上拉。
双级同步器采样输入；重复 START 读寄存器，最后一字节发 NACK 后 STOP。
`done` 为单周期脉冲，`error` 为 0 成功、1 从机 NACK、2 整笔事务超时，保留至下一笔。
有限时钟拉伸允许等待；总线长期被拉低则超时释放输出，不永久等待。
只支持点对点单主机，无多主机仲裁。

`ov5640_ctrl.sv`：`start` 时锁存 `width/height/hts/vts/quality/jpeg_mode`，
先置 PWDN/RESET，再唤醒和等待，读 `300a/300b`，只有 ID=`5640` 才写表。
写 251 项，软复位后等待，再回读 16 个关键项；全部一致才置 `configured/capture_resetn`。
默认 100 MHz / 100 kHz，RESET 阶段各 5 ms，上电稳定 20 ms，软复位/重试间隔 1 ms，
单笔事务 10 ms、每笔最多额外重试 2 次。时钟、延迟、超时和重试数保留参数用于实物校准。
`done` 脉冲；`failed/error/chip_id/last_reg` 保留供诊断。失败拉低摄像头 RESET，采集不放行；
新的 `start` 可恢复/重新配置，忙时请求忽略，系统复位会释放 SCCB。

错误码：0 成功，1 NACK 重试耗尽，2 超时重试耗尽，3 芯片 ID 不符，4 配置参数错误，5 关键项回读不符。
分辨率最大 2592×1944，宽度偶数；JPEG 宽高需为 16 的倍数，HTS/VTS 必须分别大于输出宽高。
质量为 `4407[5:0]` 的量化参数（0..63），不是软件常见的 0..100 质量百分比。
格式支持 JPEG / YUYV，RGB 和自动对焦未加入。本阶段只验证配置，不证明 DVP 输出格式/图像质量。
帧周期用 HTS/VTS 调节；PLL 沿用官方 24 MHz 输入基线，曝光自动控制仍可能延长帧周期，
具体 FPS 和 PCLK 必须实测，不能把 VTS 配置通过当成 15/30 fps 验收。

寄存器表来自用户提供的官方 camera44 `ov5640_init.c`，SHA-256：
`1152ebabd1d6e5b8cdd4ac5208acbe2e6807aea8e57132f7ce77316342839e4b`。
保留原有顺序/重复写和版权说明；254 次写中省略 3 次开闪光灯示例写，保留关闭闪光灯。
3808..380f、JPEG/YUYV 使能和质量由锁存参数替换。原始官方目录仍 Git 忽略，未修改或整体提交，
其“保留所有权利”不等于开源授权；这里没有复制官方 SCCB 函数实现，也未公开推送官方代码。
`test_m02.py` 在官方源文件存在时验证来源哈希和全部有序寄存器事实；普通干净检出不依赖该目录。
Linux v6.12 [上游驱动](https://github.com/torvalds/linux/blob/v6.12/drivers/media/i2c/ov5640.c)用于交叉核对地址/格式事实，未复制 GPL 驱动代码。

已核对本地底板 V3.9 原理图第一页 P2、第五页核心板连接，以及官方 camera44 XDC：
SCL=T10（P2.2），SDA=T11（P2.4），RESET_N=P14（P2.7），PWDN=V15（P2.18），
接口 LVCMOS33，R110/R111 各 4.7 kΩ 上拉到 3.3 V。
XCLK=W15（P2.17），旧官方顶层没有驱动此脚，只在初始化中假定 24 MHz。
现有传感器手册/应用指南说明需要输入时钟，不足以确认用户实际模组是否自带晶振。
因此本次探针不驱动 XCLK，避免与未知模组输出冲突；读 ID 失败时需核对模组/接线/时钟，不能盲加时钟。

```powershell
& ./.venv/Scripts/python.exe sim/tb/test_m02.py
```

引脚级从机模型不读取 DUT 状态；覆盖写/读、重复 START/读 NACK、所有写字节 NACK、
有限时钟拉伸、SCL/SDA 卡住、忙时请求与输入锁存、复位恢复。
控制器覆盖 20 次模拟初始化、全部有序写、16 项回读、320×240 到 640×480/YUYV、质量/VTS、
错误 ID、从机缺席、瞬时 NACK 恢复、重试耗尽、回读被篡改、参数拒绝和中途复位。
模拟 RESET/初始化不等于实物断电冷启动。

`build/vivado/m02_synth_1` 已通过独立顶层综合：421 LUT、250 FF、0 latch/BRAM/DSP，
2 个原生 IOBUF，0 综合警告/错误；只综合，不代表布局布线或上板验收。
第一次 OOC 综合会转换 tri-state，不能作为最终开漏硬件证据，已改用带 I/O 缓冲的顶层综合。

## 临时上板探针

复用 M01 的 PS7/DDR/100 MHz/复位配置，GP0 → 原生协议转换器 → AXI GPIO（`0x41200000`），
不构建 PS 应用；用同次生成的 `ps7_init.tcl` 和 bit 临时 JTAG 初始化、直接读写 GPIO。
这会复位 PS、临时替换已有 AES/M01 PL；不写 SD/Flash，也不跑 PHY/IP/网络测试。

```powershell
& ./board/prj/run_m02_jtag.ps1 -HardwareDirectory build/vivado/m02_board_demo
```

配置 DATA=`base+0`：bit0 START（上升沿），bit1 JPEG，bit2 640×480（0=320×240），
bits8:3 量化参数，bits24:9 VTS，bit30 切换诊断读页，bit31 控制器复位。
状态 DATA2=`base+8`：bits15:0 ID，16 configured，17 failed，18 busy，19 camera RESET_N，
20 PWDN，21 SCL，22 SDA，23 capture_resetn，27:24 error；bit30=1 时读 `{ID,last_reg}`。
脚本检查 20 次传感器 RESET/PWDN 初始化（前 10 次 320×240，后 10 次 640×480 JPEG，
末次质量 12/VTS 2400），有界退出并报告 ID、错误和寄存器。
以上是单次 JTAG 会话中的 20 次传感器 RESET/PWDN，不是 20 次板卡断电重启。后续的 20 次断电/上电后配置和无模组 fail-closed 已于 2026-10-11 完成，见 [M02 实板报告](../report/m02_sensor_reset_board_20261011.md)；DVP/JPEG 实际采集仍归 M03，SD/Flash 独立启动仍归 G0。
PowerShell 包装器保留独立日志并要求本次 `M02_JTAG_OK` 标志；实测 xsdb.bat 可能在 Tcl 报错后仍返回 0，
不能只判断退出码。离线测试模拟这个场景，确认包装器拒绝假成功。
