# 账号登录与临时 ML-KEM 视频方案

2026-10-13，用户确认设计并要求实现。本文独立于历史开发基线，设计不等于已验收。

## 范围

- 板卡采集/AES-GCM → USB Slave → Windows PC 密文桥 → WSS → Android 认证解密显示。
- PC 校验用户名密码，不要求用户填写固定 Bearer token；连接断开后重新认证。
- 密码保存为加盐慢哈希；失败限速，密码不进入 URL、日志、配对 JSON 或仓库。
- 配对 JSON 保留服务器地址和可信板卡公开身份；新配置不含 token/密码/私钥。
- 同账号单设备在线：新设备正确认证后显式确认接管；旧设备停止自动抢回。
- PC 串行清理旧 USB/视频会话后才交接；迟到消息/旧清理不能影响新 owner。
- 第一轮仍为单观看端；多账号群组广播未定，不自动加入。

## 密钥设计

跨端字节契约已冻结于 [suite2 协议](account_ephemeral_protocol.md)，Board/PC/Android 按同一契约实现。

- 长期板卡身份保持稳定，认证每次临时 ML-KEM 公钥；私钥不传输给手机。
- 临时 ML-KEM 私钥只在 RAM，完成解封装后销毁；手机/板卡以新共享秘密和绑定握手记录的 HKDF 建立业务密钥。
- 每次新连接/接管使用新临时密钥；长连接每 1800 秒重新握手，失败停流，不无限沿用旧密钥。
- 旧 AES/控制密钥及可重建临时私钥的种子清理；nonce/会话编号更新，旧帧不跨会话显示。
- 不把替换 JSON 中公钥和指纹当作公钥认证；ML-KEM 本身不是签名算法。
- 实现可先复用现有固定身份 KEM/双向 Finished 建立认证 bootstrap，再在此通道认证临时公钥。
  业务视频密钥必须来自临时 KEM；固定身份 bootstrap 密钥不用于视频。不据此宣称完整协议已获生产安全证明。

## 三端实现与验收

| 端 | 工作 | 必要检查 |
|---|---|---|
| Board | 临时 KEM keygen/认证交接/密钥销毁、兼容明确的协议 profile | 错误/重放/篡改拒绝、C 回归、ARM 构建 |
| PC | WSS 账号校验、单账号接管、USB owner fencing、仅转发新增控制记录 | 错密码不踢人、并发接管、旧清理竞态、TLS 拒绝降级 |
| Android | 登录 UI、新 JSON、显式接管、临时 KEM 和 30 分钟计时 | 错公钥/MAC/重放拒绝、旧图清理、timer/断线取消、APK |
| 协调 | 冻结跨语言契约、软件互操作与证据记录 | 手机、实板、软件测试分别记录，不混算 |

用户名密码认证与业务 ML-KEM/AES 独立；TLS 登录不等于板卡端到端密码协议。
使用标准库/已有依赖，不增加账号后台、群组广播或分布式服务。

## 本轮实现进度

PC/Android/Board suite2 软件已实现，账号 WSS 与真实 C/Java 临时 KEM 五窗口互操作通过，
客户端改为1785秒提前换钥、板端保持1800秒硬截止。源码检查与 ARM 预检通过不等于实板/手机验收。
用户明确只做软件验证；准确范围、退出语义与未完成项见 [协调联测记录](../report/account_ephemeral_software.md)。

## 尚未解决的安全/硬件前置

当前 SD 只有 G0 自检；新卡独立启动、640 秒十分钟例外及物理 PS_RST 测试窗已验证。
G6 完整视频 SD 自启动、可信板端熵源、长期身份私钥安全持久化仍待落实。
本次编程不授权向 SD 写真实私钥，不格式化更多介质、不烧 eFuse，不自动恢复/重刷实板。
开发态 PC/JTAG 提供种子的 profile 只能用于功能验证：若 PC 或持久种子可重建临时私钥，就不能声称对其具有前向保密。
生产 provider 必须保持 fail-closed；固定身份密钥泄露、持续板端入侵也不能靠定时换钥解决。
