# M04：异步 FIFO 与 AXI4-Stream

按 steps 实现 M03 → 原生 AMD XPM 异步 FIFO → 字节打包 → AXIS。
Ponytail 复用已安装 Vivado 的 `xpm_fifo_async`，没有自写 CDC FIFO、复制官方 IP 源码、
新增第三方依赖或临时 JTAG 快照旁路；M05 再接 DMA/DDR 和实拍保存。

## 接口与整帧提交

`camera_axis_bridge.sv` 的 `byte_in/byte_valid/frame_start/frame_end/frame_error`
接 M03 的对应输出，全部属于 PCLK 域；没有摄像头背压。
`frame_start` 与 SOI 的 FF 同周期，`frame_end` 与 EOI 的 D9 同周期。
遇到 `frame_error + frame_start`，先撤销旧帧，再存入新 SOI；
只有 error 没有 start 时，忽略同周期可能残留的旧字节。

数据 FIFO 为 8-bit BRAM 异步 FIFO；另一个 16-entry、33-bit LUTRAM FIFO 保存
`good + stored_length`。接收整帧之后才提交长度，读侧在提交前不读该帧。
坏帧提交的是实际已写入的前缀长度，读侧清理这些字节，不送入打包器。
这样 FIFO 满、长度超限和 M03 帧错误都不会向 AXIS 发送半帧，也不会污染下一帧。
FIFO 满后停止存当前帧，等 EOI/错误/下一个 SOI 发布丢弃描述符；不会复位全部 FIFO
而破坏之前已经确认的好帧。描述符不足时整帧拒收，不留下没有长度对应的数据。
预留两个描述符位置，处理旧帧错误与下一 SOI 同周期的情况。

`axis_byte_packer.sv` 支持 32/64 位，默认 32 位。首字节位于 `TDATA[7:0]`，
`TKEEP` 从低位连续有效，未用尾部为零，`TLAST` 只标记 JPEG 帧末尾，
`TUSER[0]` 只在一帧的首个 beat 置位。下游背压时所有输出保持不变。
原生 FIFO 的 FWFT 输出在时钟域内与 `empty/rd_rst_busy` 一起使用，不猜测跨域延迟。
参数和复位约定依据 [AMD XPM_FIFO_ASYNC 2026.1 文档](https://docs.amd.com/r/en-US/ug953-vivado-7series-libraries/XPM_FIFO_ASYNC)。

## 缓存上限与复位

默认 `FIFO_DEPTH=MAX_FRAME_BYTES=65536`，高水位 49152 字节；
最大合法帧 **64 KiB（含 SOI/EOI）**。缓存中还有别的帧时，即使新帧未超长度上限，
也可能因剩余容量不足被整帧丢弃。存储转发会增加一帧采集延迟，不宣称零延迟视频。
深度必须是 16..4194304 的二次幂，最大帧长为 1..FIFO_DEPTH，
高水位为 7..FIFO_DEPTH-5；参数合法不代表能装入 XC7Z020。

这是正常 M04 数据缓存，不是绕开 M05 的快照路径。M03/协议的 2 MiB 上限不改写成
已支持；之前用户的 365930 字节 JPEG 帧超出默认 M04 上限，会被拒收。
先在低分辨率采集后测最大 JPEG 长度，再决定扩大 BRAM 配额；超过芯片 BRAM 预算
则需要 DDR 级帧提交设计，不能靠小 FIFO 实现“任意大帧、任意背压、绝不输出半帧”。

共同 `resetn` 同时撤销收发状态，丢弃队列与 AXIS 未握手的 beat；已被下游接收的
数据由 M05 的共同 DMA 复位恢复处理，复位中止不当作正常 TLAST 完成。
FIFO reset 在 PCLK 寄存，符合 XPM 写时钟同步复位约定；两个时钟在初始化/
FIFO 复位恢复时必须运行，复位需覆盖有效 PCLK。不能在 PCLK 停止期间发短复位脉冲
然后假定 FIFO 已清空；M05 要协调摄像头复位/PCLK 恢复和 DMA enable。
`wr_rst_busy/rd_rst_busy` 期间禁止读写；恢复后从新 SOI 接收，不续传旧帧。

## 统计口

AXIS 域提供 `frames_queued`（合法帧已提交）、`frames_sent`（TLAST 实际握手）、
`frames_dropped`、`fifo_overflows`、`max_fifo_level`、`overflow_latched` 和高水位电平。
丢帧在结束/错误/新 SOI 时结算一次；帧外 M03 错误也计入丢帧。
长度拒收不伪称物理 FIFO 溢出，溢出锁存保持到共同复位，计数器按 32-bit 回绕。
水位来自 XPM 写侧计数，跨域读指针延迟使它保守；FWFT 有额外输出寄存位置，
统计不是“整个系统尚未发送的全部字节数”。

PCLK 的四个计数/峰值和锁存位通过 `xpm_cdc_handshake` 原子快照跨域，
不用逐位同步二进制总线或对跳变峰值使用 Gray 计数。
原生握手没有用户 reset 端口，所以握手控制继续完成正在进行的交易，避免中途撤销。
复位后统计需等待 CDC 收敛，不能把头几个周期的旧快照当作新计数；测试等待恢复后
核对全部计数清零。`frames_sent` 本就在 AXIS 域，高水位单独通过原生单比特同步器。
这些是 RTL 并行统计输出，不提前实现 AXI-Lite 地址表；PS 映射在 M05 集成。
M03 的分类错误计数仍在 PCLK 域，不能直接接 PS 数据总线；后续若需要 PS 分类读回
须同样使用快照，当前不宣称所有 M03 分类计数均已跨域。

## 复现

```powershell
& ./.venv/Scripts/python.exe sim/tb/test_m04.py
# 不在默认位置时，设为安装目录而不是 bin；Linux 也可通过 PATH 找到 xvlog/xelab/xsim。
$env:VIVADO_ROOT='D:/AmdDesignTools/2026.1/Vivado'
# 仅 OOC 综合，新输出目录，不下载板卡。-tclargs 放在最后。
& 'D:/AmdDesignTools/2026.1/Vivado/bin/vivado.bat' -mode batch -source prj/check_m04.tcl -log build/m04_synth_demo.log -journal build/m04_synth_demo.jou -tclargs build/vivado/m04_synth_demo
```

一项 runnable check，使用安装版 XSim/XPM/glbl 真模型，不替换为简化行为 FIFO。
三个配置：32-bit/1024、64-bit/1024、32-bit/65536。
各自验证 1..17 字节、200 组随机长度/时钟周期与相位抖动、恰好最大长度/多一字节、
错误与新 SOI 同周期、帧外错误、强制背压溢出、描述符饱和和复位中断。
记分板逐 beat 检查每个字节、KEEP/LAST/USER、零尾部和 stalled 输出稳定性。
还使用 M03 的自有真实 JPEG 经实际 DVP 引脚激励 → M03 → 两个原生 FIFO → AXIS：
各配置 1000 帧，每 25 帧连续发送后核对队列；真实截断 JPEG 在 VSYNC 被撤销，无前缀外泄。
1..17 字节等合成帧用于接口边界测试，不宣称是可解码 JPEG。
测试复用 M03 的自有 685-byte fixture，不依赖用户私人图片文件；未添加 Python 包。
hook 加入本项，缺少 Vivado/XSim 明确失败，不静默跳过 CDC 验证。
