# M07：GF(2^128) / GHASH

`gf128_mul.sv` 按 [NIST SP 800-38D](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38d.pdf)
Algorithm 1，MSB-first、`R = e1 || 0^120`，每周期处理一位，固定 128 周期完成一次乘法。
无查表或秘密值决定的周期数。`ghash.sv` 顺序累加 `AAD || pad || ciphertext || pad ||
len(AAD)_64 || len(ciphertext)_64`；长度以 bit 计、大端编码。
M08 传入 `H=AES_K(0^128)`，只送密文而非明文，并自行计算最终 Tag 的 AES 掩码。

## 接口

- `start && start_ready` 锁存 H、清累加值及长度，开始一条消息。
- `block_valid && block_ready` 接收一块。`block_data[127:120]` 是首字节，
  `block_bytes` 为 1..16，后续字节由硬件补零；`block_is_ciphertext=0/1` 表示 AAD/密文。
- AAD 必须先于密文；同一域内不足 16 字节的块必须是该域最后一块。
  零长度块、超过 16 字节、密文后 AAD 等错误置 `error`，之后须 `zeroize` 恢复。
- 每块完成时 `state_valid` 脉冲并输出当前 `state`，可与软件逐块对照。
  `finish && finish_ready` 自动处理长度块，最终同时给出 `state_valid` 和
  `digest_valid`；`state` 是 GHASH 值，不是 GCM Tag。
- `zeroize` 或低有效复位清 H、计数、累加值及乘法器内部状态。

## 复现与范围


仿真包含 32 组 GF 乘法、80 组 M00 逐块黄金轨迹和 20 组 NIST GCM 向量；
空 AAD/密文、非整块补零、每个中间值、最终长度块、非法输入及忙时清零通过。
NIST Tag 也与现有软件参考比对，以独立向量锚定 GHASH 位序。
结果：`GHASH_PASS gf=32 cases=100 per_block=1 reset=1`。
