# M05：原生 AXI DMA 与 DDR

两路 AMD AXI DMA Simple Mode，共用 PS HP0 的 64-bit DDR 端口；控制经 GP0。
复用安装版 Vitis 的 XAxiDma 与 XSetupInterruptSystem，不建立第二套 GIC 驱动，
不复制 DMA IP/驱动源码，不增加 Python 依赖。M05 只验证传输，AES-GCM AXIS 留到 M08。

## 接口

| 地址 | 功能 |
|---|---|
| 0x40400000 | dma_capture：S2MM，摄像头/测试流 → JPEG DDR |
| 0x40410000 | dma_crypto：MM2S + S2MM，本阶段为传输回环 |
| 0x41200000 | M02 配置 GPIO；+8 读摄像头状态 |
| 0x41210000 | 路由/统计 GPIO；+8 读选择的统计项 |

`dma_cfg[1:0]` 为 0：crypto MM2S→capture S2MM；1：摄像头→capture；
2：crypto MM2S→crypto S2MM；3：停用路由。模式切换前必须复位/停用两个 DMA，
不得在被背压的 AXIS beat 中间改变路由。`[2]` 为采集/FIFO flush。
`[7:4]` 选择 0=ID M051，1=queued，2=dropped，3=overflow，4=峰值，5=sent，
6=高水位/溢出锁存，7=PCLK 自由运行计数，8=测试流实际 stalled 周期。
统计读取保持路由和 flush 位；M04 统计沿用原子 CDC 快照，软件不直接读取 PCLK 二进制总线。

三个中断分别为 capture S2MM、crypto MM2S、crypto S2MM，接 PS IRQ_F2P。
Vitis SDT 对仅 S2MM 的 capture 将 IRQ 放在 `IntrId[0]`，另一项是 0xffff；
不能直接套用双通道示例的 RX=`IntrId[1]`。本平台原生生成的 GIC SPI 编码为 0x401d/0x401e/0x401f。
中断回调只确认/清除事件并设 volatile 标志；有界等待和复位在主循环完成。
UART 115200 输出状态寄存器、错误、中断次数和耗时。
启动时先调用一次原生 usleep 初始化计时器；安装版 xiltimer 首次 sleep 会启动并清零
全局计数，不能先采时间基准再执行首次 sleep。主机拒绝超出命令预算的异常耗时。

## 缓存与所有权

两个 JPEG 帧各 65536 bytes，独立输出包也是 65536 bytes，均另加 64-byte guard，
地址与大小对齐 64 bytes，不与别的对象共享 ARM 缓存行。
缓存打开时，MM2S 之前 clean TX；S2MM 之前 clean RX 的 CPU 写入和 guard，
DMA 完成后 invalidate RX，再由 CPU 检查数据，禁止完成后清理旧脏 RX 行覆盖 DMA 数据。
实际长度读取 S2MM_LENGTH (+0x58)，接收 BTT 始终为最大容量，
不依赖“比包短的 BTT”注入错误，因为 AMD 对该情况不保证行为。
依据 [AMD PG021 S2MM_LENGTH](https://docs.amd.com/r/en-US/pg021_axi_dma/S2MM_LENGTH-S2MM-DMA-Buffer-Length-Register-Offset-58h)。

FREE→CAPTURING→READY→ENCRYPTING→SENDING→FREE；M05 未加密采集也允许 READY→SENDING。
只有 FREE 可分配；完成检查拒绝零长度/超长；消费者明确释放 SENDING 后才可复用。
DMA 复位确认完成后，仅中止 CAPTURING，不回收 READY/ENCRYPTING/SENDING。
测试保留上一帧为 SENDING，在另一帧采集期间核对其完整校验和，并验证第三次分配被拒绝。
独立输出包的 ENCRYPTING 状态只是所有权检查，不代表本阶段进行了加密。

JTAG 只访问 ELF 符号声明的 mailbox/帧地址。空闲时 cache off；执行命令时 PS 独占缓存，
主机只轮询完成标志；完成后关闭并刷出缓存，再发布 DONE。
最后一幅实拍帧保持 SENDING、DMA 已复位并 flush 摄像头流，主机读完后用 release 释放。
这是正常 DVP→M03→M04→DMA→DDR 路径，JTAG 只运送完成的 DDR 数据，没有快照旁路。
校验和只用于传输测试，不是 GCM 认证或安全部署。

## 复位与容量边界

M02 配置完成与 GPIO flush 先在 AXIS 域寄存为无毛刺的复位请求，再经原生
xpm_cdc_async_rst 跨到 PCLK，异步置低/同步释放；
停止 PCLK 时可置低，但不得在没有 PCLK 的情况下认为 FIFO reset 已完成。
软件在整个 SCCB 重配期间保持 flush，测量 PCLK 正在运行后才放开。
`pclk_hz` 是 100 ms 窗口内的平均边沿率；JPEG 时钟可能停顿，不能把它当成峰值时钟/IO 时序测量。
M04 桥读侧也使用原生异步置低/AXIS 同步释放，读侧寄存器的 reset 不直接使用 PCLK 域信号。
摄像头仍采用 M04 整帧提交和 64 KiB 上限；超长/溢出帧被整帧丢弃，不让 DMA 接收半帧。
长期无合法帧由有界接收超时和共同复位处理；不声称已支持协议的 2 MiB 帧或以前的 365930-byte JPEG。
ponytail: 先用原生 Simple Mode 单个 in-flight 描述；需要实测更高吞吐时再引入 SG 队列。

## 复现

```powershell
& ./.venv/Scripts/python.exe sim/tb/test_m05.py
& ./prj/build_m05.ps1 -BuildName m05_demo
# 接好 OV5640/P2、JTAG、COM4；会临时替换 PL/裸机应用，不写 SD/Flash。
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo test --boot --count 32 --cache 0
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo test --count 10000 --cache 0
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo test --count 10000 --cache 1
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo camera --count 32 --cache 1
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo release --count 1
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo camera --count 1000 --cache 1
& ./.venv/Scripts/python.exe src/host/m05_dma.py build/vitis/m05_demo release --count 1
```

必须等前一个 XSDB 完全退出后再运行下一项，不能并行下载/复位/访问 APU。
XSDB 连接本机 hw_server 的 3121 端口；若未启动，可用原生 hw_server 的
`-sTCP:127.0.0.1:3121 -p0`，只绑定回环地址，不开放额外 GDB 端口。
COM4 抓日志可独立运行 `prj/capture_uart.ps1`。仅第一条使用 --boot；后续错误恢复测试
不重下 bitstream。摄像头可用 --size 320x240/640x480、--quality 0..63、--vts 1000..5000 校准，
默认 320×240/12/1968。输出使用独立 `data/captures/m05_*` 目录，含 result.json、原始 mailbox、
XSDB 日志、DMA DDR 原始读回以及按实际长度裁剪的 frame.jpg，不覆盖旧图片。
硬件/软件 build_manifest 固定 XSA、bit、ELF、PS init 和源码 SHA-256 及 owned 符号地址。

离线检查：4 模式/4000 组随机路由与 ready；10000 轮所有权状态；主机长度/地址/校验和拒绝；
实际 M05 集成的原生 XSim/XPM 停 PCLK 复位、背压计数和 Gray PCLK witness。
M04 仍另跑三配置、各 1000 帧的原生 FIFO/AXIS 回归，不用简化 FIFO 替代。
上板测试用 DDR pattern→原生 MM2S 作为发生器，覆盖 1..17 与 64 KiB 边界，
先启动 TX、延后启动 S2MM制造真实 TREADY 背压；随后连续传输，不逐包复位。
错误注入包括 RX 无源超时与 MM2S 对 HP DDR 窗口外 0x40000000 的只读访问。
不把 S2MM 写地址设到非 owned RAM；恢复后用正常包验证，不重新下载 bitstream。
