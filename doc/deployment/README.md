# 四端部署总入口

本教程对应当前开发/候选代码；v1.0.0 的历史下载和说明仍见 [旧发布页说明](../releases/v1.0.0.md)。
请始终先核对四端版本、来源提交和 SHA256，不将不同轮次的 BOOT、PC 程序、APK 和配置随意混用。

当前本机候选集合位于 `build/releases/v1.1.0-rc1/`，四包版本/哈希及软件检查见
[2026-10-31 交付记录](../../report/candidate_20261031.md)。Board 包仅本机使用；Android 包内 debug 可安装，
release-unsigned 不能安装，必须按教程使用部署者的真实签名材料及公开 CA 重新构建后再交付。
这不影响先用调试版统一验证功能，但不能把调试包的结果自动改记为正式签名版本验收。

## 部署顺序

1. [Board 教程](../../board/DEPLOYMENT.md)：构建/校验并取得本机板端候选；核对卡身份、备份和 SD 启动方式。先不要启动视频。
2. [PC 教程](../../pc/DEPLOYMENT.md)：先安装程序，建立受保护的用户数据目录和账号；准备板端身份/公开配对、TLS 及 SSH 材料。
3. [Server 教程](../../server/DEPLOYMENT.md)：只把 PC 的专用 SSH **公钥**提供给云端；独立核验云端 host key，部署受限隧道服务。
4. [Android 教程](../../mobile/DEPLOYMENT.md)：使用与 IP 证书一致的公开 CA 和持久 release 签名构建/安装 APP。
5. PC 完整 `check` 后，由用户上电并按明确开发参数启动；APP 输入账号密码、自动获取公开配对并观看。
6. 按 [统一验收表](ACCEPTANCE.md) 记录结果；升级或换证书时保留旧包、哈希及受保护备份，不直接覆盖后失去回滚条件。

### 当前地址及连接关系

继续使用 `124.70.38.245`，暂时没有域名。默认公网业务入口为 `wss://124.70.38.245:8765/stream`，
隧道 SSH 为 2222，管理 SSH 原端口保持不变。PC relay 只监听 `127.0.0.1:8765`，
由专用 SSH `-R` 映射至云端 TCP8765；云端不终止业务 TLS，不存放手机账号数据库。

不要把“网页可打开/端口可达/SSH 登录成功”当作视频或密码协议验收。
COM4 是历史调试串口，COM7 是历史视频 USB 示例；实际以本机设备和部署记录为准，不能盲猜端口。

## 文件与信任关系

| 文件/身份 | 留在哪里 | 给谁的内容 |
|---|---|---|
| 板端开发测试 ML-KEM 私钥 | 可信 PC 受保护私有目录 | 只在显式本地 USB 初始化给板卡，不给服务器/手机/SD/安装包 |
| 板端公钥和 SHA256 指纹、schema2 pairing | PC 公开数据目录 | 手机登录后取得；首次部署须独立核对指纹，不能含密码/token |
| `accounts.json` | PC 受保护私有目录 | 不给服务器、APK 或 Release；APP 只输入登录账号密码 |
| TLS 叶证书链 | PC 公开数据目录 | 由 PC WSS 提供给 Android；SAN 匹配公网 IP，不能只有内网地址 |
| TLS 叶私钥 | PC 受保护私有目录 | 不离开 PC，不给云端 |
| 专用 CA 公开证书 | 构建 APP 的可信机器、APP | 可复制；需独立核对公开证书指纹及有效期 |
| CA 签发私钥 | 部署者离线/受保护签发环境 | 不进 APK、PC 运行包、服务器或 Git |
| PC 隧道 SSH 私钥 | PC 受保护私有目录 | 不离开 PC；服务器仅收到 `.pub` |
| 服务器 SSH host key | 服务器 | PC 仅保存独立核验后的 host 公钥/指纹，不盲信 ssh-keyscan |
| Android release keystore | 部署者受保护签名环境 | 仅给签名构建，需安全备份；不同签名不能直接覆盖同包名 APP |

这三类指纹不可互相替代：**板端 ML-KEM 身份 pin**认证板端，**CA/TLS 身份**认证业务入口，
**SSH host key**认证中转主机。账号登录也不替代其中任何一项。
CA 证书指纹按证书 DER 计算，不等于对 PEM 文本文件运行 `Get-FileHash` 的结果；
候选 ZIP/BOOT/APK 的文件 SHA256 则对文件原始字节计算。

## 启动和维护约定

- 先核对旧服务/端口归属，正常 Ctrl+C 停止自己运行的 PC 实例；不杀未知进程，不同时打开视频 CDC。
- 普通 `eyepqc run` 不注入板端身份；SD 开发态须按 PC/Board 教程显式提供两个 `--dev-*` 参数。
- `FAULT` 或未知固件不自动重刷/JTAG 复活；保留脱敏日志，按故障教程人工处理。
- 修改账号后正常重启 PC relay 才加载新快照。修改服务器地址须同步 WSS 证书 SAN、APP endpoint 和 SSH known_hosts。
- 证书更新先备份旧材料并验证新链/有效期；若更换 CA，需要配套新 APK 信任配置，不能只替换叶证书后跳过验证。
- 卸载保留用户数据不等于已经备份。升级前把私有材料备份到有适当访问控制的可信位置，不发聊天或公网网盘。

## 验收与正式发布

开发侧软件测试只是交付前检查。部署执行及最终验收由用户统一进行，所有物理/公网/手机项保持待填。
候选包不是生产安全认证，调试 PC 知道板端身份/seed 的事实不因正式 APK 签名而改变。
详细阶段与正式版前置见 [交付计划](../release_plan.md)。
