## 固定基线

参数来源与摄像头 P2 引脚见 [官方例程研究](../report/vendor_examples.md)。
原始例程只作为依据，不参与新硬件构建，不照搬旧生成文件。

| 项目 | M01 配置 |
|---|---|
| 器件 | xc7z020clg400-2 |
| DDR | 用户确认两颗 H5TC4G63EFR-RDA；每颗 4 Gb / x16，合计 1 GiB / 32 bit；DDR3L、533.333 MHz |
| DDR 时序 | Custom / DDR3_1066G；CL8、CWL6、tRCD/tRP 8 cycles、tRAS 36 ns、tRC 51 ns、tFAW 50 ns |
| CPU / PS 输入时钟 | 666.667 MHz / 33.333333 MHz |
| UART0 | MIO 14..15、115200、8N1；MIO Bank 0 为 3.3 V |
| GEM0 / MDIO | MIO 16..27 / 52..53；MIO Bank 1 为 1.8 V；125 MHz |
| SD0 / 卡检测 | MIO 40..45 / MIO10；为同平台 FSBL 的 SD 冷启动启用，不写入现有 SD 卡 |
| 网络 | 192.168.1.10/24、网关 192.168.1.1、TCP echo 端口 7 |
| MAC | 02:00:00:00:01:10，仅用于隔离实验网络；多板使用时改为唯一地址 |
| PL | FCLK0 100 MHz → heartbeat；LED H15、LVCMOS33 |
| PL 复位 | FCLK_RESET0_N → proc_sys_reset，同步释放 peripheral_aresetn |
| 定时器 / 中断 | SCU private timer 50 ms；SDT 的 XSetupInterruptSystem 与 GEM 共用 GIC |

DDR 时序依据 [SK hynix H5TC4G63EFR Rev.1.3 数据手册](https://datasheet.lcsc.com/datasheet/pdf/aea45ff70742b3df7465cb4aa7642654.pdf?productCode=C37953994)
第 30–31 页；533 MHz 采用保守 CL8/CWL6，不依赖可选 CL7 档。实物不是 Micron，
不能继续套用旧 MT41K part preset。新增核心板 V2.5 原理图第 5/8/10 页标明 1.35 V，
但原理图标注的内存为 NT5CC256M16；本项目使用用户提供的海力士型号配置。
PS IP 显式选择 CLG400，封装延迟由本机对应 xc7z020 的原生 preset 计算，
不复制旧例程中与 xc7z010 相同的封装长度。PCB 延迟仍为官方示例的 0.25 ns / DQS-to-CLK 0；
新增走线 CSV 是否适用于实物版本待确认，尚未据此完成板级校准。

用户提供的 CF7020B 对应规格书 V1.2 第 10–11 页的 7020 核心板型号，
不等同于已确认 PCB 为 V2.5；走线校准仍未完成。新核心板原理图
第 11 页为 YT8521SC-CA，而当前 AMD lwIP 2.2.0 和官方 echo 旧 BSP 均无 YT8521 分支，
未知 PHY 会落入 Marvell 初始化。现已加入最小 YT8521 适配：双 ID 检查、铜口模式/
1.8 V strap 校验、保留供电配置、RX 2 ns/TX 1.95 ns、全双工协商及超时；
板上已识别正确 ID，但尚未验证实际链路及数据收发。底板另有 PL 网口，
最后的网络验收必须连接 PS 网口；当前离线阶段无需接网口。详细资料来源见官方研究记录第 7 节。
M01 不接摄像头、不加 DMA/密码核，也不使用 U18 外部 PL 时钟或 N16 按键复位。
1 Hz LED 波形每 0.5 秒翻转；LED 电平极性仍以实物为准。

已安装 Zynq-7000 器件支持，并实测 `get_parts xc7z020clg400-2` 找到器件。
准备 README 的 Python 环境和 Icarus Verilog 后，在仓库根目录执行：

```powershell
& ./prj/build_m01.ps1 -ToolRoot 'D:/AmdDesignTools/2026.1'
```

顺序为离线测试 → 创建 BD → 综合/实现/bitstream → XSA → Standalone/lwIP BSP → ELF。
输出目录已存在时拒绝覆盖；重新构建使用 `-BuildName m01_retry1` 等新名字。
所有工程和日志放在忽略的 `build/`。该命令不会编程 FPGA 或写入板卡 Flash。

默认输出：

- `build/vivado/m01/m01.xsa`（包含 bitstream）；bit 文件在 `m01.runs/impl_1/system_wrapper.bit`。
- `build/vivado/m01/{ip_status,timing,utilization,drc}.txt`。
- `build/vitis/m01/m01/build/m01.elf`，平台内另生成 FSBL。
- `build/vitis/m01/build_manifest.json`：输入 XSA、应用、PHY 适配及生成驱动、ELF 的 SHA-256，`board_validated=false`。

软件单独构建时使用 `vitis.bat -s prj/build_m01.py`；可用环境变量
`EYEPQC_M01_XSA` / `EYEPQC_M01_VITIS` 指定 XSA 和全新工作区。
统一构建脚本只使用它刚生成的新 XSA，不自动回退到旧/官方 XSA。
Vitis CLI 即使脚本异常也可能返回 0，因此脚本检查构建状态和新 ELF/清单。

## 自检程序

`src/ps/src/m01.c` 只使用 BSP/lwIP，不另建驱动框架：

- UART 启动、状态码、断言和异常日志；错误停机保留现场，不自动复位掩盖问题。
- 在拥有的 64 KiB BSS scratch 上运行 BSP 内存测试；先关闭 DCache，再打开缓存写入、
  flush/invalidate 后读回；每分钟重复缓存路径。这不是全 DDR 容量/压力测试。
- `M01_ASSERT` 始终启用；同时注册 Xil_Assert callback。BSP Release 自带的 NDEBUG
  可能禁用驱动内部断言，应用不依赖它替代返回值检查。
- 全局计时器与 SCU tick 相互检查；主循环处理 TCP 250/500 ms 和 ARP 5 s 定时器。
- 每秒检查网口状态，每 10 秒输出 DDR、连接、echo 字节、异常和定时器统计。
- echo 最多四个并发连接；完整复制 pbuf 链后一次 tcp_write，空间不足时让 lwIP 重试，
  不释放未接收的数据；FIN 关闭失败由 poll 重试。该测试服务不是 M11 控制协议。

`src/ps/src/m01_yt8521.inc` 只插入本次新工作区的 BSP 共用 PHY 分派入口，
初始化和重连均复用原生 GEM/SLCR 代码，不改安装目录或官方源码。
重连不重置已经配置的 PHY；原生恢复入口增加失败检查，避免失败被误报 link-up。
`M01_YT_TX_DELAY=13` 保留板级延迟校准入口。芯片 reset 最多 1 秒、协商最多 5 秒；
底层 MDIO 事务仍使用原生 GEM 驱动，不声称覆盖 GEM 时钟故障的硬件卡死。

启动应出现 `M01 BOOT`、`DDR PASS uncached+cached`、`ECHO READY`，随后 `M01 STAT`。
`ECHO READY` 只说明 TCP 监听已建立，不代表 PHY 已协商或网络已通过。

## 临时 JTAG 与串口采集

先核对构建清单的源码/ELF/XSA 哈希，并确认 Vitis `_ide` 中的 bit 和 ps7_init.tcl
与同一 XSA 中对应条目一致。以下两条命令在两个终端顺序执行，先打开串口：

```powershell
& ./prj/capture_uart.ps1 -Port COM4 -Seconds 120
& ./prj/run_m01_jtag.ps1 -Workspace build/vitis/m01_cf7020b_v2
```

采集器使用系统 SerialPort，115200/8N1，禁用 DTR/RTS，不发送 UART 数据；
日志使用新文件，拒绝覆盖。JTAG PowerShell 入口校验清单绑定与 XSA 内 bit/init，
并要求 XSDB 完整启动成功标记；本机 XSDB .bat 即使 Tcl exit 1 也可能返回 0，
不能仅判断退出码。Tcl 脚本复位 PS、运行同平台 ps7_init、配置 PL、
下载 ELF 并启动 A9#0；这是易失性下载，会替换当前 RAM/PL 程序，不写 SD/Flash。
`rst -system -stop` 后不要重复 `stop`：本机 XSDB 会对已停止的核报错。
